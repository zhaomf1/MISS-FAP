# UI 布局可读性重构设计

## 目的

让维护者能从代码中快速找到屏幕区域的绘制方式、各运行状态的显示规则和对应按键操作，便于后续调整与排错。

## 目标与非目标

- 目标：整理 `ui_layout.c` 的职责，集中表达屏幕尺寸、区域坐标、焦点编号和图标位置；将初始化、输入处理和状态刷新拆成名字明确的小函数。
- 目标：用中文注释说明运行阶段对应的标题、状态文字、颜色、数值和进度条表现。
- 目标：修正右侧开始/停止/舱门/消音图标重叠的问题，使当前焦点只显示对应图标。
- 非目标：不改变界面分区和现有业务状态机，不修改温控、电机或按键硬件行为，不新增公共 UI API。

## 方案比较

- 方案一（选定）：继续使用单个 `ui_layout.c`，通过内部小函数、命名坐标和明确的状态刷新函数整理职责。保留 `ui.h` 的公共入口，Keil 工程无需新增源文件。
- 方案二：将布局、状态渲染和按键处理拆成多个源文件。边界更强，但需要新增跨文件接口并调整 Keil 工程配置，当前范围暂不需要。

## 设计决定

- 公共入口保持 `ui_layout_init()`、`ui_layout_ready()`、`ui_layout_key()`、`ui_layout_process()`。
- 初始化拆成页面框架、顶部栏、温度区、计时区、延迟降温区和操作按键区的创建函数；坐标和尺寸集中在命名常量或区域定义中。
- 焦点使用有名称的枚举项，导航表和可操作条件按对应控件排列，避免散落的数字索引。
- 按键流程拆为导航、编辑、提交命令和长按重复处理；保持现有按键映射和设定范围。
- 状态刷新拆为顶部状态、温度、孵育计时、延迟降温、操作按键和编辑光标。每个函数只负责一个区域。
- 图标对象采用独立位置定义，并按焦点索引控制可见性；停止符号保持直角空心正方形。
- 用中文注释/状态映射说明空闲、运行、延迟、降温、保存、完成、错误和报警时的显示规则；业务状态优先级及已有文案保持不变。

## 约束与验收

- 不改变屏幕 320x240 分区、现有中英文界面文案和命令含义。
- `ui.h` 的对外函数签名保持不变，Keil 工程源文件清单保持不变。
- UI 静态检查通过；`ui_layout.c` 主机语法检查通过；完整应用测试若受环境/文件占用影响，需明确报告。
- 通过代码结构可直接找到每个页面区域的创建函数和状态刷新函数；停止、舱门、消音图标互不重叠。
